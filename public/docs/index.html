Introduction

Base URL: https://outreach.seannocode.com 
Push leads in, read what came back out, and run the sequences that sit between the two.

Everything answers in the same shape, so one field tells you whether a call worked:

```json
{"success": true, "message": "ok", "data": {}}
```

List endpoints add a `meta` object with `page`, `per_page`, `total` and `last_page`.
Take `?per_page=` up to 200 and page with `?page=`.

<aside>A machine-readable OpenAPI spec is at <b>/docs/openapi.yaml</b> and a
Postman collection at <b>/docs/collection.json</b>.</aside>

## Two actions are switched off by default

Approving a draft (<code>POST /api/messages/{id}/approve</code>) and un-suppressing an
address (<code>DELETE /api/suppressions/{email}</code>) both return 403 unless an
administrator turns them on. They are held back because each removes a safeguard
rather than just moving data: the first sends a real email with nobody having read
it, the second resumes emailing a person who asked us to stop.

## Before you push contacts

Read `GET /api/suppressions` first. Pushing an address that is on that list is
accepted and then silently does nothing, so a caller that does not check keeps
offering people who already opted out and never learns why.

Authenticating requests

To authenticate requests, include an Authorization header with the value "Bearer YOUR_API_KEY".

All authenticated endpoints are marked with a requires authentication badge in the documentation below.

Create a key in the dashboard under Settings → API keys. It is shown once.

Each key carries one or more abilities and an endpoint accepts only the ones it lists:

  • read — every GET
  • write — push contacts, edit and reject drafts, manage automations and mailboxes
  • approve — approve a draft so it sends

Give a key only what it needs. A tool that just pushes leads needs write, not read.

Wrong key gives 401; a valid key without the right ability gives 403, and the message says which ability was missing.

Counts across the system in one request.

Overview

requires authentication

Counts across the system in one request, instead of paging through every list to work them out.

A rate comes back as null rather than 0 when nothing has been sent, because 0 would read as "nobody replied" instead of "no data yet".

Example request:
curl --request GET \
    --get "https://outreach.seannocode.com/api/stats" \
    --header "Authorization: Bearer YOUR_API_KEY" \
    --header "Content-Type: application/json" \
    --header "Accept: application/json"
const url = new URL(
    "https://outreach.seannocode.com/api/stats"
);

const headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json",
    "Accept": "application/json",
};


fetch(url, {
    method: "GET",
    headers,
}).then(response => response.json());

Query Parameters

ISO date. Narrows the sent, reply and bounce counts to that window. Totals and the queue are current state and are not narrowed. e.g. 2026-08-01.

Request      

GET api/activity

Headers

Authorization        

Example: Bearer YOUR_API_KEY

Content-Type        

Example: application/json

Accept        

Example: application/json

Query Parameters

level   string  optional    

One of info, warning, error. e.g. error.

event   string  optional    

Exact event name. e.g. send_failed.

retryable   boolean  optional    

Only entries the system can retry. e.g. true.

since   string  optional    

ISO date. Only entries logged on or after it. e.g. 2026-08-01.

per_page   integer  optional    

Rows per page. Clamped to 200. e.g. 50.

page   integer  optional    

Which page to return. e.g. 1.
